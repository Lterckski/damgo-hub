- **Fixed a real infrastructure bug: `/projects` (and any multi-relation query) crashed with `DriverAdapterError: ConnectionClosed`.** Root cause, confirmed directly rather than guessed: the local dev database behind `DATABASE_URL` (`prisma dev`'s `template1`) is **PGlite** — a WASM-embedded Postgres, not a real server (`SELECT version()` reports `wasm32-unknown-linux-gnu ... emcc`). PGlite doesn't handle genuinely concurrent connections; a query with 2+ relation includes makes the `@prisma/adapter-pg` driver open multiple pool connections and run their sub-queries in parallel, and PGlite closes one mid-query. Reproduced precisely: every single-relation include worked, every combination of 2+ relations failed the same way, every time. Fixed in `lib/prisma.ts` by capping the `pg.Pool` to `max: 1` (forces node-postgres to queue queries sequentially instead of opening concurrent connections) — scoped to `localhost`/`127.0.0.1` URLs only, not `NODE_ENV`, so a real production Postgres server never gets artificially capped to one connection. This was a latent bug in every multi-relation `include` in the app, not something the Project Proposals work introduced — `/projects` (owner + members + links) was just the first query complex enough to trigger it.

- **Fixed a real, systemic bug: every `Select` in the app could show its raw value instead of a label before its dropdown was ever opened.** Made undeniable by a screenshot of the Team Lead picker showing a raw member cuid (`cmtgqddha0000fxhzal6ytwgh`) instead of a name — but the same root cause was quietly present everywhere else too (Task Type showing "PITCHING" not "Pitching," Project showing the raw `__none__` sentinel, Priority showing "MEDIUM," etc. — just easy to miss since most enum values happen to look plausible unformatted). ## Architecture Decisions

- **Meetings are planned in Damgo Hub but happen elsewhere.** Unit `16` schedules meetings, selects participants, stores an optional physical location or external meeting URL, and lets participants propose agenda items. Only the Leader and Assistant Leader (`org:admin`) can accept/decline proposals or directly add, edit, order, and remove final agenda items; regular members only propose and read the final agenda. Participants receive individual Resend emails for invitations, important meeting changes, removal/cancellation, and 24-hour/1-hour reminders through Trigger.dev; email failure never rolls back a meeting mutation. There is no in-app call, Liveblocks meeting room, live notes, recording, or quote capture; unit `17` is retired. Meeting and agenda data stays relational in PostgreSQL.
- shadcn/ui's current CLI offers a choice of underlying component library (Base UI / React Aria / Radix UI) — went with **Base UI** (CLI default) + the **Nova** preset (Lucide + Geist).
- Dark mode uses Tailwind's default `prefers-color-scheme` media variant, not shadcn's generated class-based toggle — no `ThemeProvider`/manual switch in this project, per `ui-context.md`.
- shadcn's own component-internal CSS variable names (`--background`, `--primary`, `--border`, etc.) are kept as-is in `globals.css` (components under `components/ui/*` are never edited) with values pointed at the `ui-context.md` palette; the doc's own semantic names (`bg-base`, `text-copy-primary`, etc.) are layered on top via additional `@theme inline` mappings.
- This shadcn build uses **Base UI's `render` prop**, not Radix's `asChild`, for trigger composition (e.g. `<DropdownMenuTrigger render={<Button .../>} />`) — every future component using a trigger/child pattern needs this, not `asChild`.
- RBAC runs on Clerk B2B Organizations, not a custom role field — see `architecture-context.md`'s Auth and Roles Model and `team-roster.md`.
- **Route protection is resource-based, not middleware path-matching.** `proxy.ts` is a bare `clerkMiddleware()` — no `createRouteMatcher`. Clerk's dev server actively deprecation-warns on `createRouteMatcher`-based middleware gating ("can diverge from how Next.js routes requests and leave protected resources reachable"). Real protection: `app/(app)/layout.tsx` redirects unauthenticated visitors for every page under it; every `app/api/*` route checks `auth()` itself and returns `401`. `03-auth.md` and `architecture-context.md` were updated to describe this — don't reintroduce `createRouteMatcher`-based gating in later units.
- Clerk's `Theme`/`Variables` type isn't exported from `@clerk/ui`'s root — use `Appearance` from `@clerk/ui` instead (see `lib/clerk-appearance.ts`).
- Clerk's Backend SDK org-membership calls (`lib/organization-roles.ts`) use `auth().orgId` from the calling admin's own session as the organization ID — there's only one org, so no separate lookup/env var needed.
- Primary navigation is a bottom floating dock (icon-only, hover-label), not a side sidebar — a deliberate, explicit layout choice, not a placeholder. Don't reintroduce a side sidebar for the main app shell without asking. The roadmap uses floating React Flow `Panel`s inside its canvas; the future ideas board can reuse that pattern if appropriate.
- **All money is PHP, integer centavos, formatted only through `formatPHP()`** (`lib/currency.ts`) — see `architecture-context.md` invariant 8 and `07-financial-tracker.md`'s Currency section. Don't add a currency field or format an amount ad hoc anywhere.
- **Deferred-relation pattern**: when a spec needs a foreign key to a model that doesn't exist yet (e.g. `Transaction.penaltyId` before `18-penalty-tracker.md`, `Task.projectId` before `11-project-proposals.md`), add it now as a plain nullable column (no `@relation`), and turn it into a real Prisma relation only once the target model actually exists. Don't invent the target model early just to satisfy a relation.
- `Penalty` (once built in `18-penalty-tracker.md`) auto-creates an `APPROVED` `Transaction` when a monetary penalty is resolved, linked via `Transaction.penaltyId` — see that spec's "Link to the financial ledger" section. This was decided ahead of `18`'s own build turn, at the user's request, since the team's penalties are mostly fines.
- Server pages that need both an initial data fetch and later client-side mutations query Prisma directly for the initial render (like `members/page.tsx`, `finance/page.tsx`, `tasks/page.tsx`) rather than calling their own `GET` API route — the `GET` routes still exist (per each spec's Routes section) for client-side refetches/future consumers, but aren't the page's own data source.
